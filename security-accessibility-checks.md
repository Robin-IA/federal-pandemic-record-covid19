## Code security

### `S-cd5758` String rendered as markup or code (innerHTML)

- **Must fix** · found by explorer-checks
- **Where:** `index.html:291`

```text
document.getElementById("pages").innerHTML = M.pages.map(p => {

Review: Lines 294-297 interpolate url ("https://" + p.url) and x.ts into two href attributes without esc(). Both come straight from data/pages-monthly.txt via build_site.py:124-128, which splits lines without validating them. The https:// prefix rules out a javascript: URL, but a double quote in that file would break out of the attribute. Fix: const url = esc("https://" + p.url); and ${esc(x.ts)} in both hrefs.
```

**Recommended fix:** Trace what reaches this sink. If any part comes from data (archive.org metadata, captured page text, the URL, user input), escape it or build nodes with textContent. Clear it only if every part is a literal or already escaped, and name the escaping function.

## Accessibility (WCAG 2.2 AA)

### `A-3fc18c` No main landmark

- **Must fix** · found by review · WCAG 2.4.1
- **Where:** `index.html:144`

```text
<header> and <nav> are landmarks, but the four view sections are not inside <main>, so a screen reader user cannot jump past the masthead and tabs.
```

**Recommended fix:** Wrap the four <section class="view"> elements in <main id="main">. This also clears the landmark-one-main and region advisories.

### `A-af8ffa` Search box has no visible label

- **Must fix** · found by review · WCAG 3.3.2
- **Where:** `index.html:152`

```text
Only a placeholder and aria-label; the placeholder disappears as soon as typing starts.
```

**Recommended fix:** Add <label for="q" class="eyebrow">Search titles</label> above the input (the .eyebrow style already fits) and drop the duplicate aria-label.

### `A-b4d27c` Result count changes are not announced

- **Must fix** · found by review · WCAG 4.1.3
- **Where:** `index.html:153`

```text
<span id="count"> is rewritten on every filter and keystroke but is not a live region.
```

**Recommended fix:** <span id="count" role="status"></span>. Screen readers then announce "N of M documents" after each change without moving focus.

### `A-1a6195` Chart event labels are below 4.5:1 in light mode

- **Must fix** · found by review · WCAG 1.4.3
- **Where:** `index.html:21`

```text
Measured: --event #a86a12 on white is 4.43:1 for 10px bold text (dark mode is 7.52:1).
```

**Recommended fix:** Change the light-mode --event to #965e0f (5.38:1 on white). It is the same hue, slightly darker. Dark mode needs no change.

### `A-24aaff` Month filter works only by clicking small chart bars

- **Must fix** · found by review · WCAG 2.1.1, 2.5.8, 1.1.1
- **Where:** `index.html:250`

```text
svg.querySelectorAll(".bar").forEach(b => b.onclick = ...) — the bars are SVG rects with no keyboard access. Measured 21.7px wide on a pitch under 24px, and as low as 0px tall. The svg is role="img" labelled only "Documents per month", so the monthly counts have no text equivalent.
```

**Recommended fix:** Add a Month <select> beside the chart caption, with one option per month that carries its count ("Mar 2020 (412)") plus "All months", wired to the same st.month toggle. That gives keyboard access (2.1.1), an equivalent control that meets target size (2.5.8 exception) and the chart's data as text (1.1.1). Keep the bar clicks as a mouse shortcut. Change the caption from "Click a month to filter" to "Choose or click a month to filter".

### `A-fdd24c` Filtering throws keyboard focus to the top of the page

- **Must fix** · found by review · WCAG 2.4.3
- **Where:** `index.html:267`

```text
The facets change handler calls render(), which rebuilds #facets through innerHTML and destroys the focused checkbox. "Clear filters" (line 274) sets itself hidden while it has focus.
```

**Recommended fix:** In the change handler: const id = e.target.id; render(); document.getElementById(id)?.focus(). The checkbox ids are already stable. In the clear handler, move focus to the search box before hiding the button: document.getElementById("q").focus().

### `A-6c8b81` Placeholder months are marked by colour alone

- **Must fix** · found by review · WCAG 1.4.1
- **Where:** `index.html:297`

```text
In each page's month grid, placeholder months differ only by class isph (red text). The sparkline that shades them is aria-hidden.
```

**Recommended fix:** Add text to the row: ${x.ph ? " · placeholder" : ""} after the KB figure on line 297. The legend already defines the word.

### `A-411875` Sticky tab bar can cover the focused link entirely

- **Must fix** · found by review · WCAG 2.4.11
- **Where:** `index.html:53`

```text
Measured: Shift+Tab back up the document list scrolled two links ("Clinic", "316079 c coronavirus guideline") to y=0-17px, wholly under the 46px sticky nav.
```

**Recommended fix:** Add html { scroll-padding-top: 56px } so the browser scrolls focused elements clear of the nav.

### `A-2bd7a3` Search box border and dimmed chart bars are too faint

- **Must fix** · found by review · WCAG 1.4.11
- **Where:** `index.html:80`

```text
Measured: the .search border (--rule) is 1.34:1 against the input and 1.25:1 against the page, and the input background is 1.07:1 against the page, so the box is barely visible. With a month selected, the other bars dim to --accent-soft at 1.26:1 (dark 1.27:1), and the chart's shape disappears.
```

**Recommended fix:** Give .search border-color: var(--muted) (5.70:1 light, 6.41:1 dark). For the chart, stop dimming the other bars: keep them at --accent and mark the selected month with stroke: var(--ink); stroke-width: 2 on .bar.sel. The selected month is already named in the count line, so selection does not rest on colour alone.
